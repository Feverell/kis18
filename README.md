## Алгоритмическая логика

Поиск точного решения был бы слишком затратным. Поэтому используется следующий эвристический подход:

1.  Обходим и осматриваем все доступные вершины.
2.  С помощью алгоритма Дейкстры (вес открытых ребер - 0, закрытых - 1, неизвестных - вероятность, что они обвалились) выделяем в графе дерево, выбирая для каждой вершины самый перспективный (с точки зрения суммы весов) путь до нее.
3.  В этом дереве оцениваем ожидаемый профит от открытия каждого закрытого ребра. Это можно сделать динамическим программированием от листьев к корню. Ожидаемый профит раскрытия каждого следующего ребра пересчитывается через ожидаемые профиты соседних ребер с учетом того, что эти соседние ребра можно и не раскрывать.
4.  Если для каждого закрытого ребра посчитанный ожидаемый профит отрицателен, завершаем, заключая, что дальнейшее исследование шахты нецелесообразно.
5.  В противном случае открываем ребро с лучшим ожидаемым профитом, нас возвращают на стартовую позицию и переходим к пункту 1.

## 🗂 Структура

* `Types.hpp` — Псевдонимы типов, легковесные типы
* `Graph.hpp` — Топология и состояние графа
* `Solver.hpp` — Основная логика принятия решения
* `Agent.hpp` — Оркестатор (ходит по графу, вызывает Solver).
* `main.cpp` — Точка входа, парсинг исходной карты/

## ⏱ Алгоритмическая сложность
На каждую итерацию вызова Solver:
* **Dijkstra:** $O(E \log V)$
* **Topological Sort & DP:** $O(V + E)$
* **BFS (в Агенте):** $O(V + E)$
