## Алгоритмическая логика

Поиск точного решения был бы слишком затратным. Поэтому используется следующий эвристический подход:

1.  Обходим и осматриваем все доступные вершины.
2.  С помощью алгоритма Дейкстры (вес открытых ребер - 0, закрытых - 1, неизвестных - вероятность, что они обвалились) выделяем в графе дерево, выбирая для каждой вершины самый перспективный (с точки зрения суммы весов) путь до нее.
3.  В этом дереве оцениваем ожидаемый профит от открытия каждого закрытого ребра. Это можно сделать динамическим программированием от листьев к корню (в качестве корня можно взять начальную вершину). Динамика пересчитывается следующим образом:

$$dp(v)=profit(v)+\sum_{x\in childs(v)}\max(0,probability(v,x)*dp(x)+(1-probability(v,x))*(dp(x)-cost))$$
$$dp(e)=dp(e.to)-cost$$

По смыслу $dp(v)$ - матожидание прибыли от доступа к недоступной вершине $v$; $dp(e)$ - ожидаемая прибыль от открытия закрытого ребра $e$. В формуле пересчета, в частности, учитывается, что в дальнейшем ребра можно и не раскрывать.

4.  Если для каждого закрытого ребра посчитанный ожидаемый профит отрицателен, завершаем, заключая, что дальнейшее исследование шахты нецелесообразно.
5.  В противном случае открываем ребро с лучшим ожидаемым профитом, нас возвращают на стартовую позицию и переходим к пункту 1.

## Структура

* `Types.hpp` — Псевдонимы типов, легковесные типы

## Алгоритмическая сложность
Solver:
* Каждый вызов Solver работает за $O(E\log(V))$ (Дейкстра за $O(E\log(V))$, DP за $O(V)$)
* Solver вызывается 1 раз на каждое открытие ребра

Agent:
* $O(V+E)$ времени (BFS) на формирование обращения к судье, если не вызывается Solver
* $O(V)$ обращений к судье на каждую неисследованную вершину
